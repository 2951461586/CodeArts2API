# registry

## 职责

维护「对外可用的模型清单」以及别名解析：把一个客户端请求的模型名，解析成上游真实的模型。

清单可热更新 —— 上游拉取成功后整体替换；拉取失败时用内置兜底清单，网关不至于没有模型可用。

## 边界

- **只依赖 `codearts`**（消费 `BuiltinModel`）。
- **不发起网络请求**：拉取由 `server` 做，结果喂进来。这样清单逻辑可以脱离网络单测。

## 关键决策

- **别名是兼容层，不是路由层。** 客户端习惯写 `gpt-4o` / `claude-sonnet-4`，
  这些名字在上游并不存在。2026-10 免费通道下线后，原有一批模型 ID 全部消失，
  别名统一重映射到当前可用的积分模型（见 `adr-0005`）。
- **兜底清单不带上下文长度。** 上游的模型清单接口不返回 `context` / `max_output`，
  内置兜底清单因此留空，控制台显示「—」而不是编一个数字。
- **`StreamOnly` 只是省一次空枪。** 它标记上游只支持流式的模型，让网关不必每次都先打一次
  注定失败的非流式请求；真正的降级（流式 + 本地聚合）由 `server` 做。

## 不在本模块

模型解析失败时的对外表述（404 + 可用清单）属于 `server` 与 `apierr`；
本模块只回答「解析成功了吗、解析到哪个模型」。

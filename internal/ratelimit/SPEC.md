# ratelimit

## 职责

按 API 密钥限制请求速率与在飞并发：令牌桶管 QPS，计数闸门管并发。

存在的理由只有一个 —— **防止失控客户端烧光账号积分**。循环重试、Agent 死循环、
多标签页同时跑，都能在几分钟内把额度打光，而网关这边原本没有任何刹车。

## 边界

- **叶子包**：不依赖任何内部包，也不认识 HTTP。配置是一个普通结构体，
  时钟是一个 `func() time.Time` —— 测试因此不需要 sleep。
- **不做排队**。超限立即拒绝并给出 `Retry-After`，网关不维护等待队列、不占住连接。
- **不做公平性**。见 `goal` 的「非目标」：单机个人网关，不承诺密钥之间的配额分配。
- **不做鉴权**。它只看到已经通过鉴权的密钥，因此桶的数量被已签发密钥数封顶，不需要回收。

## 关键决策

- **先查并发、再扣令牌。** 并发被拒时不必回滚令牌；顺序反过来就得处理回滚。
- **并发拒绝的 `Retry-After` 固定 1 秒。** 并发没有可计算的时间信号（不像令牌桶能算出
  「还差多少令牌、按什么速率补」），给一个让客户端下一轮再试的最小值即可。
- **`release` 必须可重复调用且并发安全。** 漏调会让该密钥在 `Concurrency` 次请求之后永久 429 ——
  这是本模块唯一能造成的持久故障，因此用 `sync.Once` 兜住重复释放。
- **`QPS <= 0` 视为关闭而不是拒绝。** 设置层已保证正整数，这里是除零的最后一道防线。

## 不在本模块

- **什么算一次请求、按哪个 key 计数**：由 `server` 的 `withRateLimit` 决定（挂在鉴权之后）。
- **429 的响应形状与 `Retry-After` 头**：状态码与 `error.type` 由 `apierr` 决定，
  协议风格（OpenAI / Anthropic）由 `server` 的 `errStyle` 决定。
- **默认值**：住在 `store.DefaultSettings()`，本模块不持有默认值。

## 明确推迟

- **全局并发兜底**（多密钥合起来打满上游）。当前定位是单机单用户，密钥数不会多到需要它。
- **按上游账号的并发上限**（对齐「每账号 3 个并发会话」）。它能从根上消掉 `TM.00001041`，
  但属于上游适配问题，与「自我保护」是两件事。

# store

## 职责

网关全部运行期状态的唯一归宿：API 密钥、请求日志、设置、账号池，以及它们的落盘与迁移。

同时是账号池的调度者：按可用性挑下一个账号、记录成功/失败、标记熔断。

## 边界

- **只依赖 `codearts`**（持久化 `Account` / `Session` 类型）。
- **不认识 HTTP**，也不认识模型清单。

## 关键决策

- **对外只给浅拷贝，不给内部指针。** `Account` 的字段会被请求路径（`MarkAccountResult`）
  与控制台并发读写，直接交出内部指针就是数据竞争。`Session` 指针可以共享 ——
  它构造完成后不再原地修改，续期是整体替换指针。
- **落盘必须串行 + 临时文件名唯一。** 并发 `Save` 曾共用同一个 `<path>.tmp`：Windows 上
  报「文件被占用」而失败（调用方多半忽略错误 → 状态静默不落盘），Linux 上可能把写了一半的
  临时文件 rename 成正式状态文件。现在由 `saveMu` 串行化，临时文件以 `0600` 创建
  （里面是 STS 凭据与 refresh_token），fsync 后再 rename。
- **schema 带版本号，迁移就地做。** 状态文件版本高于本程序时拒绝启动并提示升级 ——
  静默降级会让新版本写的字段被旧程序丢掉。
- **旧模型名在启动时迁移。** 免费权益通道下线后，历史设置里的默认模型名在上游一律报错，
  启动时重映射到当前默认模型。

## 已知限制

- **不支持多进程并发写。** `Save` 有原子性（不会写坏），但没有读-改-写合并；
  两个进程共用一个状态文件会丢更新（last-writer-wins）。
